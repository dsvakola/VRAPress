# Contributing to VRAPress

Thank you for helping build a focused, secure, and dependable CMS.

## Before contributing

1. Check the roadmap and existing issues.
2. Discuss substantial features before implementation.
3. Keep each change focused and free of unrelated formatting.
4. Never include credentials, personal data, local configuration, uploads, logs, or backups.

## Development workflow

1. Fork the repository and create a descriptive branch from `main`.
2. Follow `docs/CODING_STANDARDS.md`.
3. Add or update tests for changed behavior.
4. Update relevant documentation and changelog notes.
5. Open a pull request explaining the problem, solution, security/data impact, and verification evidence.

## Acceptance principles

- Security and content integrity come before convenience.
- Database changes require migrations and upgrade tests.
- User-facing workflows must be accessible and responsive.
- New dependencies require a clear maintenance and security justification.
- Maintainers may revise or decline changes that conflict with the product direction.

For vulnerabilities, follow `SECURITY.md` instead of opening a public issue.
